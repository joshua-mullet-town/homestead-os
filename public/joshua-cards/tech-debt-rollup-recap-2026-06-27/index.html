GiveGrove Tech-Debt Rollup

Recap of all 7 cleanup items, what changed in the code, and what's worth a quick test. June 2026.

This was a batch of seven dependency / housekeeping items — the kind of stuff that accumulates and starts to slow things down or block future upgrades. Each one is its own pull request, so they can be reviewed and merged independently.

A note on testing: a few of these are pure removals — we deleted things that were already unused, so there's literally nothing new to click on. Others changed real behavior (a chart, the session-replay player) and are worth a look. Each item below is tagged so you know which is which.

Overall rule of thumb: if the lights are still on, it's working. The build passes and the app boots; the items below just call out the few spots where it's worth eyeballing the actual feature.

📋 For David — the short version

Seven small PRs, mostly dependency cleanup. Three of them touch something a person can actually see and are worth a 2-minute look on Give Grove Mullet: the donut chart on the event dashboard, the session-replay video player, and a single event date label. The other four are invisible plumbing (Node version bump, a removed unused library, a removed unused polyfill, and a new build check in CI) — nothing to click, just confirm the app still loads and deploys.

Specific links and exactly-what-to-look-for are under each item.

1. Upgrade to Node 24 LTS

Main app: PR #1523  ·  Ticketing API: PR #72
Real change Worth a look

What changed

Moved both codebases off Node 20 onto Node 24 (the current long-term-support version). This is the runtime everything builds and deploys on. It updated every deploy workflow, deleted some old custom Node-20 build-container scripts we no longer need, and refreshed the locked dependency versions.

One small piece of real code changed in the cloud functions: the "new user signup" handler was rewritten from the old Firebase function style to the newer one (beforeUserCreated), because the old style isn't supported the same way on the new runtime. Same behavior — copies a phone number into the new user's profile on signup.

What to test

Confirm the app still deploys cleanly and loads. Then, the one functional thing to spot-check: create a new account (especially a phone-number signup) and confirm the user gets set up normally. That's the only behavior that touched real code.

2. Add a build check to CI

PR #1542
Real change (infra) Nothing to click

What changed

Added an automatic "does it actually build?" check that runs on every pull request before it can be merged. We added this after a previous change froze the beta site for a week — a small type-annotation slip got merged because nothing was verifying the front-end could compile. Now it can't happen again: if the app doesn't build, the PR is blocked.

What to test

Nothing to click in the app. This is a guardrail in our pull-request pipeline. You'll just notice that PRs now show a "Build Check (Vite)" step that has to pass.

5. Remove the moment date library

PR #1550
Real change (tiny) One thing to glance at

What changed

Removed moment — a big, old date-formatting library that the app barely used. It was only being used in one place: formatting the date shown on an event card (e.g. "June 19, 2026"). We replaced that single line with the browser's built-in date formatting, which produces the exact same output. The whole library is now gone.

What to test

Open an event card and confirm the date still reads like "June 19, 2026" — full month name, day, year. That's the only spot this touched.

6. Upgrade the chart library (chart.js v2 → v4)

PR #1552
Real change Worth a look

What changed

Jumped the charting library forward by two major versions (it was years out of date). There's exactly one chart in the whole app: the donut chart on the event dashboard that breaks down totals by category. The new version changed how charts get configured, so we rewrote the chart's setup to match — legend, tooltips, sizing, and the dollar-formatting on hover were all carried over to produce an identical result.

We verified it pixel-for-pixel on Give Grove Mullet: same donut size (476×330), same slices, same legend, and hovering a slice still shows the dollar amount like "$51,205.00". Bonus: this upgrade also fully removed moment from the project — the old chart library was secretly dragging it back in.

What to test

Open an event's dashboard and confirm the donut chart looks right — correct slices, legend showing each category, and hover a slice to confirm the dollar tooltip shows up (e.g. "$51,205.00").

7. Upgrade session-replay (rrweb)

PR #1554
Real change Worth a look — the trickiest one

What changed

This is the "watch a recording of a user's session" feature in the super-admin area. It was running on a preview ("alpha") version of the underlying library, and the goal was to move it onto a proper stable release. No app code changed — it's purely a version bump of the session-replay packages.

An honest caveat (important)

We discovered the only "stable" release of the video-player piece is itself broken — it literally can't play recordings. We confirmed this against the library directly, not just our app. So that one piece stayed on the known-good preview version you already had, while the rest of the session-replay machinery moved to stable. Net result: nothing about the feature changed for users — recordings record and play exactly as before — and we're now on the best combination available.

What to test

Go to the Session Recordings list, open one recording, and confirm two things: (1) the player loads (no "failed to initialize" error), and (2) when you hit play, you actually see the recorded page content — not just a moving cursor on a blank screen. Both of those were verified working live.
